==== known side-effect: Claude Code install-method marker wiped ====
Symptom (observed 2026-05-08, post-install): `claude upgrade` emits warning:
  "Running native installation but config install method is 'unknown'.
   Fix: Run claude install to update configuration"

Cause: Step 5's wholesale `rm -rf ~/.claude/` removed Claude Code's own install-method
config marker (which lives inside ~/.claude/, alongside PAI's content). The PAI v5.0.0
installer rebuilt ~/.claude/ with PAI files but did NOT restore Claude Code's own
metadata — that is not the PAI installer's responsibility, it is Claude Code's.

The same wipe explains Step 7's terminal `pai --print` post-install error: the
installer's final hand-off tried to launch Claude Code non-interactively, but with
no install marker present the launch path was incomplete.

Resolution applied: 2026-05-08, `claude install` re-run on marrmini (interactive
shell). Output: "Claude Code successfully installed! Version: 2.1.133. Location:
~/.local/bin/claude". Future `claude upgrade` invocations should no longer warn.

Generalisation for the comparison report (Step 10): any "wholesale remove ~/.claude
+ reinstall PAI" migration creates this metadata gap. Worth a one-line warning in
upstream's migration guide, or a `claude install` step in the v5.0.0 installer
itself.

==== Skill listing budget overflow (v5.0.0 + 45 skills) ====
Source: `/doctor` output captured 2026-05-08, marrmini, claude 2.1.133.

Symptom: "45 skill descriptions dropped" warning visible in welcome panel.
The model receives skill names but no descriptions for these 45 skills,
degrading auto-routing. Skills remain invocable by name.

Detail per `/doctor`:
- Per-entry cap exceeded by 4 skills (descriptions individually too long):
  ISA, BeCreative, Interview, +1 more.
- Aggregate budget overflow: 45 descriptions would need 7.7% of context;
  current `skillListingBudgetFraction` setting = 1%.
- Opt-in cost to keep all descriptions: ~16k tokens per session,
  faster rate-limit consumption.

Causal context for issue #166: this is a function of v5.0.0's 45-skill
default. The fork's Algorithm v3.7.0 ships 22 skills (culled set) and
does not exhibit this warning on marrair — fewer skills fit the same
budget without truncation. The skill-set growth between v4.x and v5.0.0
is the structural cause, not a regression introduced by this migration.

Remediations available (no choice locked):
1. Live with truncation. Zero token cost; user invokes skills by name.
2. `/skills` to disable unused skills. Per-skill choice; reduces aggregate.
3. Raise `skillListingBudgetFraction` in settings.json. Trade context
   budget for descriptions; ~16k tokens/session ongoing.
4. Trim individual SKILL.md description fields (especially for ISA,
   BeCreative, Interview — 4 skills exceeding per-entry cap regardless
   of aggregate budget).

Worth surfacing in Step 10's comparison report as a v5.0.0 baseline
finding, and in Step 11's design doc as a port-strategy input. If
porting the fork's curated skill subset is HIGH priority, this issue
may auto-resolve as a side-effect.
